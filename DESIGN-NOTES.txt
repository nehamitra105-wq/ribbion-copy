DECISION
Build a mobile milestone-story creator for the friend who already collects meaningful fragments and wants the gesture to feel personally authored. One relationship, one occasion, one complete storybook. The example is Maya's birthday. Graduation remains a supported occasion, not a second product.

Core insight to test: the missing ingredient is often meaning, not more media. Existing memories can suggest a through-line; only the giver can confirm it and add the moments no camera captured.

Opinionated principles:
1. Keep the meaningful effort. Automate organization, make interpretation and personal writing editable.
2. A memory is not permission to share it. Explicit selection; visible message sources; preview the exact recipient output.
3. A gift should not become a signup request. Export a self-contained HTML keepsake with embedded photos.
4. Give navigation a neutral identity. Soft sage, taupe and lilac gradients distinguish formats; personal imagery belongs inside the selected memories and keepsake. Use restrained glass controls, regular native sans-serif headings and plain labels.

COMPLETE PROTOTYPE PATH
Home or reminder → occasion/formats → select memories → choose/correct thread → edit title/chapters/personal meaning → recipient preview → wrap → download → recipient experience.
Secondary paths: add a manual memory/photo/message; start a new recipient with sparse context; edit milestone; toggle quotes/reminders; resume draft; delete local data. Trivia and capsule each demonstrate one format interaction.

WHY THIS MVP
Product thinking: narrows to the already-thoughtful friend and a storytelling job, instead of spanning lazy gifting, shopping, relationship CRM and social networks.
Depth and communication: exposes three testable tensions—authorship versus automation, missing context versus intake friction, and source selection versus private sharing.
Craft: a coherent warm/dark visual world, a two-axis mood interaction with accessible sliders, explicit selection feedback, tactile book preview, a complete recipient outcome and reduced-motion support.

WHAT IS WORKING
Manual text/photo import, memory inclusion/exclusion, source labels, custom title/thread, mood and audience settings, editable chapter reflections and final note, chapter ordering, quote inclusion, draft persistence, recipient paging, self-contained downloadable HTML. New recipients start with no assumed data.

WHAT IS SIMULATED OR LIMITED
No AI API, automated message parsing, iMessage/Gmail integration, calendar connection, push delivery, server storage, authentication, scheduled delivery or secure capsule locking. Thread suggestions are illustrative starting points; they are not semantic inference from imported content. The reminder is an in-app preview. Multiple draft snapshots are stored in this browser; each has its own title, selected memories and writing. Large photos can exceed browser storage; an in-tab warning asks users to export before closing. The sample shows one generated photograph in several crops and fictional messages. Replacing it with consenting participants' actual material is essential for user validation.

AUTHENTIC TEST PLAN FOR THE COLLABORATOR
Use 3–5 people who already save memories and make milestone gestures. Ask each to bring a small set of material they are comfortable using.
1. Compare a ready-written tribute with the editable thread-first flow. Observe what they reject, rewrite and keep; ask whether they feel ownership. Do not invent prior test results.
2. Observe whether the missing-memory prompt adds something meaningful or feels like homework. Allow skipping.
3. Ask what they would otherwise make and whether this outcome earns its extra effort. Record whether they actually choose to send the result.
4. Have the recipient experience the file. Check whether they can open it without help, recognize the relationship, and understand the giver's meaning.
Use actual observations to choose the final flow. This prototype is the starting hypothesis, not proof.

HOME AND FEATURE AUDIT — AFTER COLLABORATOR FEEDBACK
This is a design hypothesis informed by the supplied rubric, not a claim that judges prescribed these features.

Product thinking
The job: “For this person's milestone, help me turn the things I remember into a gesture that feels like me.” The primary user already cares and invests effort. Success is not speed alone: it is an authored gift the giver wants to share and the recipient recognizes as theirs.

Homepage order, derived from the second supplied wireframe:
1. One upcoming occasion establishes recipient and deadline. Start opens format choice; Continue returns to the actual saved editing step. No duplicate upcoming list for the same event.
2. Exact photo/message counts expose the available material before asking for work. The sample set is labelled; no false claim of synchronization. Counts link to review and import.
3. Three visual format previews communicate different recipient experiences: trivia asks the recipient to participate; storybook provides narrative and personal interpretation; time capsule gives a memory a future moment. Neutral gradient surfaces and small physical forms replace the unrelated photographic hero.
4. A draft appears only after creation begins. It resumes real stored state. No fabricated project library.
5. Home/You/Plus keep the familiar minimum navigation. Plus starts another recipient; You manages local material and reminder preferences. The reminder is a demonstrable entry point directly into the current relationship.
Removed: decorative kicker labels, stock-like photo hero, redundant “See all” for only three formats, repeated occasion rows, mandatory mood setup and empty draft placeholders.

Depth of thinking and communication
Memory selection earns its friction because it determines what the recipient will see. A suggested thread is correctable because the giver knows the meaning of the relationship. A personal chapter note supplies meaning unavailable from media alone. Recipient preview earns a separate step because a private message may be appropriate as source material but not as published text. These are consequential decisions to demonstrate in the competition video.
Mood is optional: an expressive interaction is useful only when it changes the gift. It adjusts example title language and audience handling, but it must not block a giver who already knows what to say. The three main stages are memories, meaning and editing; mood is outside the step count.
The template layout follows the user's wireframe, but implementation depth stays focused: the complete storybook provides the storytelling evidence. Trivia and capsule are explicitly representative prototypes, not three fully built products. Do not pitch secure locking, scheduled delivery or generated trivia as implemented.

Craft
The home is a useful starting screen rather than a photographic landing page. Charcoal and low-saturation gradients establish a neutral shell; each format uses a distinct preview object so color alone does not convey its function. Personal photos remain in the material review and final story where they have semantic purpose. Native sans typography, visible touch targets, keyboard focus, reduced motion, persistence and actual export support the emotional tone with reliable behavior.

Platform and friction decision
Keep this MVP as a mobile web prototype. Embedding it in Figma would narrow distribution to people already willing to use a professional design tool; that is a different audience assumption. An installed app could eventually justify reminder and integration affordances, but this prototype does not establish that need. A recipient should be able to open the result without becoming a user. The self-contained HTML download tests this direction, although file-sharing convenience must still be validated; a hosted private link would be a later implementation choice.

What to test before claiming differentiation
Give a thoughtful friend the same small memory set and compare this flow with their normal photo album or message-writing workflow. Observe where they add meaning, which assistance they reject, time spent importing, whether they finish, and whether they choose to share. Ask the recipient which detail felt personal. Compare template-first and occasion-list-first entry with actual tasks. The rubric rewards defensible reasoning; a good-looking screen and passing browser tests do not establish product value.
